# Implementation Plan: Full Dashboard Functionality

**Goal:** Transform the dashboard from a static mockup into a fully functional, real-time security application using the authenticated GitHub identity and Gemini API.

---

### Phase 1: Real Repository & File Selection
**Goal:** Allow users to browse their own repositories and files to select a scan target.

#### Task 1.1: Sidebar Repository List
- **Backend:** Ensure `/api/user/repos` returns all accessible repos.
- **Frontend:** Update `Sidebar.tsx` to fetch and display the user's real GitHub repositories using the OAuth token.

#### Task 1.2: File Tree Browser
- **Backend:** Create `/api/repos/{owner}/{repo}/files` to fetch the file tree of a selected repository.
- **Frontend:** Implement a simple file browser in the Sidebar or a modal to select a specific file for scanning.

---

### Phase 2: Live Scan & Persistence
**Goal:** Connect the dashboard to the real agentic scan process and save results.

#### Task 2.1: Wiring the "Run Scan" Button
- **Frontend:** Update the dashboard's "New Scan" flow to take the selected file path and trigger the real SSE stream (`useAgentStream`).
- **Frontend:** Show a "Scanning..." state in the UI while the agent is working.

#### Task 2.2: Findings & Patch Storage
- **Backend:** Modify `backend/main.py` and `backend/agents/scanner.py` to save confirmed findings and patches into the PostgreSQL/SQLite database at the end of a scan.
- **Backend:** Link findings to the `User` who ran the scan.

---

### Phase 3: Real Data Dashboard
**Goal:** Replace all mock data with real database records.

#### Task 3.1: Real Findings Table
- **Backend:** Update `/api/findings` to query the `Finding` and `Patch` tables for the logged-in user.
- **Frontend:** Update `DashboardPage.tsx` to fetch this real data on load instead of using `MOCK_VULNS`.

#### Task 3.2: Dynamic Statistics
- **Backend:** Implement an endpoint for dashboard stats (count by severity, patched vs. open).
- **Frontend:** Update the summary cards to reflect real metrics from the database.

---

### Phase 4: Patch Review & Application
**Goal:** Make the "Auto-Patch" button functional.

#### Task 4.1: Patch Preview Modal
- **Frontend:** Create a `PatchModal.tsx` to display the "Before vs. After" code diff generated by the agent.
- **Frontend:** Add an "Apply Fix" button (simulated or real PR creation).

---

### Phase 5: Polish & Error Handling
- **Frontend:** Add toast notifications for scan success/failure.
- **Frontend:** Implement skeleton loaders while fetching repository lists.
- **Backend:** Add robust error handling for GitHub API rate limits.
